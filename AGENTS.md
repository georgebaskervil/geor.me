## Learned User Preferences

- Prefers autonomous dependency-rolling design that does not require routine human review.
- Treats browser console warnings (referrer-policy, Robustext SharedArrayBuffer, CORB on telemetry) as non-actionable when they are graceful degradation with no functional impact.
- Prefers direct execution for release tasks (commit, sync, push) once fixes are validated.
- Does not want large R2-hosted model files proxied through Rails; fix access with R2/Cloudflare CORS instead.
- When optimizing visual effects, preserve pixel-perfect appearance unless explicitly told otherwise.
- Text-shadow on all text and carousel slide blur are core design elements; do not remove them for performance work.
- Site blocks crawlers (`noindex, nofollow`); do not add SEO or robot-facing affordances.
- Live push updates should only fire when user-visible display fields change, not on every timer tick or timestamp refresh.
- CI image push and deploy (`build-push`) must never run on pull requests—only on push to `main`.

## Learned Workspace Facts

- `geor.me` production/CI Docker builds run on Linux amd64, so `Gemfile.lock` must include `x86_64-linux` alongside local macOS platforms.
- The homepage Robustext embed is same-origin, must keep pointer/keyboard interactivity, and must be fully destroyed/re-instantiated via Stimulus `robustext-embed` on carousel slide mount/unmount (Emscripten breaks with inline scripts and cloneNode remounts).
- Page content renders inside a CRT barrel-filter stack (`.scanlines` outside; SVG `feDisplacementMap` on `#crt-content` and `.crt-shell` overlays inside `foreignObject`—not CSS `filter: url(#barrel)` on HTML, which misaligns `userSpaceOnUse`); Lenis smooth-scrolls the inner content. The custom cursor, Oneko, and click hearts live in `.crt-shell` inside the CRT filter (intentional design, not outside the warp); cursor and Oneko use `data-turbo-permanent` with saved state so they stay seamless across Turbo navigations.
- App responses set COEP and COOP to `unsafe-none` site-wide so third-party iframe embeds work; production layout does not load the Umami tracking script; `/data` still embeds the Umami share iframe.
- Distraction-mode ChatCCP uses `@mlc-ai/web-llm` (WebGPU) with `SmolLM2-360M-Instruct-q4f16_1-MLC`; weights download from Hugging Face via WebLLM (not R2, not Rails-proxied). Requires WebGPU (Chrome/Edge primary; Firefox often too slow).
- Distraction-mode and homepage carousel HLS clips use intentional low-quality ("potato") encodes; shared defaults in `scripts/hls_encode_settings.sh` (426×240, CRF 34, ~350k cap); re-encode existing segments via `scripts/reencode_hls_potato.sh`.
- Lunar background texture (`lunar-texture.avif`) must be generated via Chromium/Playwright SVG capture plus `avifenc --lossless` (`bun run generate:lunar-texture`); CRT displacement map stays PNG for SVG `feImage` compatibility; `starfield.svg` and `turbo-loading-spinner.svg` live in `app/images/` (no CSS data-URI inlines; Vite does not re-inline `app/images` assets).
- Frontend assets: Stimulus controllers lazy-load via `import.meta.glob`; Phaser/Plotly load from `/public/vendor/` on demand via `loadVendorScript.js` (they crash the Vite transform pipe and cannot be bundled); ChatCCP WebLLM loads from `/vendor/web-llm/index.js` via `loadWebLLM.js` (`bun run sync:web-llm` copies `@mlc-ai/web-llm`—Rolldown cannot re-bundle its prebuilt `lib/index.js`); route CSS uses Vite SCSS entrypoints under `app/stylesheets/entries/` injected by the `RouteStylesheets` concern. Production `vite:build` emits a Workbox service worker (`config/vite/pwa.js`, copied to `/service-worker.js`) that precaches Vite JS/CSS/fonts and runtime-caches same-origin static assets (not HTML, `/api/*`, or `/cable`).
- Route-specific CSS is assigned in `RouteStylesheets#assign_route_stylesheets` as `@route_stylesheet_entries` and rendered in the layout after `core.scss` (with `data-turbo-track="reload"`); do not rely on `content_for` from controller `before_action` — it does not reach the layout here. Homepage route CSS entry includes embed partials (images, taskstack, robustext, posts, etc.); `/taskstack` uses `page-taskstack.scss` alone; Eclecticon routes share `entries/eclecticon.scss`; distraction mode loads only after the nav button via `distractionmode-launcher` and `data-distraction-deferred`.
- Turbo navigations use [`turbo-view-transitions`](https://github.com/palkan/turbo-view-transitions) when `<meta name="view-transition">` is present and `prefers-reduced-motion` is not `reduce`; `#site-main` has `data-turbo-transition="page"`. Without View Transitions, `turbo-loading` blur overlay still applies.
- Production/dev web server is Iodine (`bundle exec iodine`), not Puma; Docker and Procfile both start Iodine. Live footer/homepage counters use Action Cable (`LiveStatsChannel`, WebSocket at `/cable`) with `LiveStats` ticking on `Iodine.run_every` (no blocking Rack SSE); broadcasts only when `time_since` or `current_day` change, not every timer wake. Client is `app/javascript/live_updater.js` (`@rails/actioncable`, JSON poll fallback to `/api/v1/stats/live`). `config/cable.yml` uses `async` (single worker); scale with `redis` adapter + `REDIS_URL` when running multiple Iodine workers. `config/initializers/permessage_deflate.rb` tunes WebSocket compression for speed (`BEST_SPEED`, `HUFFMAN_ONLY`, 11-bit window) on small JSON frames.
- GitHub Actions: `build-push` in `.github/workflows/ci.yml` runs only on `push` to `main` (never on `pull_request`—same-repo PRs still receive deploy secrets). Dependabot auto-merge (`.github/workflows/auto-approve.yml`) requires repo secrets `APP_ID` and `APP_PRIVATE_KEY` (GitHub App); `scripts/wait-pr-checks-for-merge.sh` waits only on Socket and Snyk checks (all others ignored).
